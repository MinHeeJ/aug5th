# 구현 전 확인 OQ Notes

Phase 8 hardening 산출물로, 1차 공통기능 구현 범위 밖이거나 원문에서 정책이 확정되지 않은 항목을 구현 전 확인 gate로 고정한다.

| OQ ID | 관련 요구 | 확인 gate | 현재 1차 구현 정책 | 구현 전 확인 필요 사항 |
|---|---|---|---|---|
| OQ-HARDEN-001 | REQ-050 | 기능 권한 최소 구조 | 별도 기능 권한 관리 화면·테이블·API는 만들지 않는다. 1차 접근통제는 메뉴 접근권한과 R09 역할 세션으로 제한한다. | 후속 범위에서 기능 단위 권한이 필요한지, 메뉴 권한과 분리할 권한 action/read/write 모델이 필요한지 확인한다. |
| OQ-HARDEN-002 | REQ-027, REQ-030 | 메뉴 권한 충돌 우선순위 | 1차 구현은 대상별 메뉴 접근권한 저장과 effective 조회 구조만 제공한다. 사용자·조직·역할 권한이 충돌할 때의 최종 우선순위는 업무 확정 전 임의 확장하지 않는다. | USER > ORGANIZATION > ROLE 같은 명시 우선순위, deny 우선/allow 우선 정책, 기간 조건 적용 여부를 확정한다. |
| OQ-HARDEN-003 | REQ-013 | 조직 변경사유 | 조직 관계 변경 시 changeReason 필드를 저장 가능한 구조로 두되, 필수 여부와 표준 코드 목록은 1차 범위에서 강제하지 않는다. | 변경사유 필수 여부, 사유 코드그룹 사용 여부, 승인/검토 단계 필요 여부를 확정한다. |
| OQ-HARDEN-004 | REQ-023, REQ-026 | 승인자 자동기록 | 사용자 역할 저장 요청은 승인자 기록 필드를 보존하지만 다단계 승인 workflow 또는 외부 결재 연동은 만들지 않는다. | approvedByUserId를 로그인 사용자로 항상 자동 기록할지, 관리자가 대리 승인자를 선택할 수 있는지, POSITION 역할의 승인자 기록 원천을 확정한다. |

## Release Guard

- 위 OQ는 현재 phase에서 업무 API나 화면을 추가 생성하지 않는다.
- 범위 밖 기능을 route에 노출해야 할 경우 `frontend/src/routes/outOfScope.tsx`의 비업무 `준비 중` placeholder만 사용하고 범위 밖 `/api/...` 호출은 추가하지 않는다.
- 후속 구현에서 위 항목 중 하나가 확정되면 이 문서를 업데이트하고 관련 contract test를 먼저 추가한다.
